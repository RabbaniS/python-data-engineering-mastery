# Day 21: Capstone, Review, and Publishing

## Topics
- Integrating Python, SQL, and PySpark skills
- Automated tests and repeatable setup
- Documentation, diagrams, and demo output
- Scope, tradeoffs, and future improvements

## Quick theory
- A capstone is strongest when it solves one understandable problem end to end.
- A reproducible README should state prerequisites, setup, run commands, sample output, and known limitations.
- Tests and data-quality checks provide evidence that the pipeline works; a polished dashboard alone does not.
- A good portfolio explains decisions honestly and makes it easy for another person to run the project.

## Practice
Publish a small end-to-end data pipeline. Include a diagram, sample data or retrieval instructions, tests, quality checks, and a short demo. Review the project as if you were onboarding a teammate.

## Quick check
1. Can a new contributor reproduce the result from a clean setup?
2. What evidence shows that the pipeline is correct and rerunnable?
3. Which limitation or next step should the README disclose?
